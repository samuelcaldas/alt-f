Bootloader & Flash Limits

The stock D-Link U-Boot bootloader enforces strict partition copy sizes when reading the kernel and initramfs from flash into RAM. The firmware generation pipeline (mkfw.sh) enforces these exact thresholds:

Target Profile Max Kernel (uImage) Max Rootfs (urootfs) Max Extra Partition Rootfs Execution Mechanism
DNS-323 / DNS-321 1,572,864 bytes (1.5 MiB) 6,488,064 bytes (6.18 MiB) N/A (single NOR flash) SquashFS (XZ/LZMA) from NOR flash
DNS-325 / DNS-320 / DNS-320L 3,145,728 bytes (3.0 MiB) 3,145,728 bytes (3.0 MiB) 104,857,600 bytes (~100 MiB) Dual Partition: Base SquashFS + UBIFS extra
DNS-327L (ARMv7) 3,145,728 bytes (3.0 MiB) 4,194,304 bytes (4.0 MiB) 81,788,928 bytes (~78 MiB) Dual Partition: Base SquashFS + UBIFS extra

U-Boot NAND Read Constraint Note

Although devices such as the DNS-325 have a 5MB flash partition assigned for kernel and rootfs, stock U-Boot's bootcmd hardcodes reading 0x300000 (3,145,728 bytes). Any kernel or initramfs exceeding 3 MiB would trigger a "Bad Data CRC" error on boot. Alt-F strictly bounds firmware components within these safety limits.

Disk Capacity & Drive Sizes

Thanks to modern Linux 4.14 kernel drivers and 64-bit LBA addressing:

  • Alt-F fully supports GPT (GUID Partition Table) partition layouts alongside legacy MBR.
  • Hard drives larger than 2TB (such as 3TB, 4TB, 6TB, 8TB, and 12TB drives) are recognized and formatted without capacity limits.
  • Advanced Format (4Kn and 512e) drives are automatically aligned to 4096-byte boundaries for maximum read/write throughput.
